# 產品需求：以五階段共通流程引導產品盤查

更新：2026-09-07。本文件為目前產品需求入口；`planning-baseline` 保留原始規劃，不代表目前實作完成度。依據與限制見[舊資料分析](architecture/LEGACY_PURPOSE_ANALYSIS.md)，實作邊界見[技術架構](05_ARCHITECTURE.md)。法規、有效 PCR 與已核准 ADR 的優先順序仍依根目錄 `AGENTS.md`。

## 目的與使用者

幫助有產品碳足跡需求的企業，知道每個生命週期階段應蒐集什麼資料、如何選用係數、如何得到可追溯的結果，減少重複輸入與人工計算。核心是產品盤查工作流程，不要求企業先完成組織型溫室氣體盤查。

企業管理者建立產品與人員權限；盤查人員及經授權的資料提供者蒐集數據、選用係數與附上證據；審核者檢查資料與例外；企業管理者依階段及項目結果找出改善方向。供應商限縮填報權限是協作需求，不代表目前已提供獨立供應商入口。

## 完整使用流程

1. 建立組織、產品版本及盤查專案，記錄宣告／功能單位、期間、邊界與廠場。
2. 選用經審查的 PCR／規則版本，確認各階段適用性、需要的資料及例外理由。
3. 依下表蒐集各階段活動與證據，選用明確分母單位及版本的係數。
4. 驗證缺漏、單位、分配與情境假設，明確執行計算，建立不可變 Calculation Run。
5. 檢視逐項結果、階段總和與產品總和，送審或補正；資料變更後建立新 run。
6. 從指定 run 匯出盤查清冊、結果與證據索引，查看歷次輸入／結果差異，支援後續改善分析。

## 五階段資料需求

五階段共用一個盤查專案、係數目錄、單位目錄與計算引擎；不同階段有不同欄位，不建立五套獨立計算服務。

| 階段 | 應蒐集資料 | 設計與驗證邊界 |
|---|---|---|
| 原料取得 | BOM 原物料與包材投入、供應來源、原物料運輸重量與距離 | 原料與運輸各有明細；同類材料彙整不得遺失來源或重複計算 |
| 製造 | 產品產量、全廠能資源、分配基礎、製造廢棄物與委外運輸 | 全廠總量、產品分配量與每宣告單位量須可區分；保存分子、分母、期間及理由的結構化分配仍是缺口 |
| 配送銷售 | 配銷路線、運輸工具、數量／重量及距離 | 地圖距離只作來源輸入；重量距離換算由受控規則計算 |
| 使用 | 使用情境、壽命、頻率、單次能資源／耗材消耗、單位及來源 | 使用情境是資料與受控公式，不執行自由文字程式碼；目前通用乘積不代表涵蓋所有 PCR |
| 廢棄處理 | 處理量、處理方式、各方式占比與運輸 | 占比的基礎與互斥情境必須明確；不可把資料列數占比當重量占比，或把同一重量的替代係數估算當成多筆實際流向加總 |

所有階段保留原始值、單位、轉換與公式版本、係數版本、資料期間、來源、估算理由及證據。不適用或排除必須有理由，空白不等於零。

## 範圍與優先順序

| 優先順序 | 能力 | 現況／下一步 |
|---|---|---|
| 核心 | 一個產品盤查貫穿五階段、按活動種類輸入、係數查詢與導入 | 已有基礎；以三類舊產品案例檢查欄位與流程缺口，不直接匯入舊答案 |
| 核心 | 受控單位、PCR／係數版本、計算、證據、審核、匯出 | 保留現有實作及安全約束；公式的領域核准與工程驗證分開 |
| 核心 | 已凍結 run 的輸入／結果差異 | 保留既有 lineage／diff；屬追溯功能，不等於任意產品的減碳效益比較 |
| 後續完整切片 | BOM 結構與彙整、全廠資料分配、可重用使用模式、廢棄處理占比 | 舊資料有需求證據，但現有扁平活動列／文字情境不能視為已完整實作；先確認語意再擴充模型 |
| 後續完整切片 | 熱點排序與不覆寫基準的減碳情境比較 | 舊版有熱點原型及改善目的；不是已完成的情境比較系統。比較前需檢查單位、邊界與規則可比性 |
| 協作與整合 | 供應商指派、可重用範本、業務系統資料匯入 | 依實際使用流程逐項實作，不先增加服務或通用規則平台 |

不包含自動查驗／核定、碳標籤簽發、完整組織盤查、CBAM／碳費申報或微服務平台。沒有適用 PCR 時如何進行研究，須由領域人員確認；舊報告的合規推論不構成本系統核准依據。

## 驗收條件

- 一筆活動可追到盤查版本、階段、原始資料、係數、單位、公式及證據。
- 計算、送審與結果是否過期的判斷使用相同快照讀取規則；查詢不建立或覆寫 run。
- 項目總和等於階段總和與產品總和；顯示四捨五入不改變原始數值。
- 修改活動或更新係數不覆寫歷史 run；組織範圍與角色限制持續有效。
- 滑鼠、衛生紙、瓶裝水作為候選案例；每例須先處理失效參照、外部連結、假設、單位與公式依據，經領域審查後才能建立正式 Golden Case。
- 使用階段另以電扇、電鍋的不同情境檢查模型能否表達；有工作表不等於有完整生命週期案例。
- 工程測試通過、舊資料對帳、人工 UAT 與領域核准分別記錄，不以其中一項代替其他項目。
