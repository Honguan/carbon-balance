## 結論

原專案是「根據產品碳足跡計算共通架構之計算系統」，另以「產品碳排不卡關」參賽。目的在於讓企業知道各階段應蒐集什麼資料，使用內建係數搜尋降低填報成本，透過同一套五階段流程計算產品足跡，再從結果尋找改善方向。

共通架構指共用的盤查流程及按階段區分的資料需求，不代表所有產品使用完全相同公式。原作者採「需求分析 → 參考 PCR／BOM／全廠資料 → 用產品案例調整模型 → 系統實作」的計畫；原報告對 ISO 符合性與跨產品泛用性的宣稱是研究主張，本次沒有據此認定合規或公式正確。

現行四層、版本化目錄與不可變計算架構應保留。需要修正的是正式產品定位、文件與實作狀態的一致性，以及 UI 內承擔共用快照組裝的責任；不需要改回 PHP 或拆五個服務。

### 對製造分配的判斷

可確認的是「應依實際可解釋的分配基礎」，尚不能確認某家工廠應採重量、工時、件數或經濟價值。若已選定相同期間、相同單位且可相加的基礎，以下是比例定義的數學推導，而不是通用 PCR 公式：

```text
標的分配比例 = 標的產品的分配基礎量 / 共用製程所有受分配產品的基礎量
標的期間分配量 = 共用活動總量 × 標的分配比例
每宣告單位活動量 = 標的期間分配量 / 該期間標的產品的宣告單位產量
```

因此舊表 C7 寫的「全廠／標的」不能直接當作乘在全廠消耗量上的占比；分配與每單位正規化也不能混為同一欄。分母必須大於零，分子／分母須同基礎、同期間；產品專用的直接量不再重複分配。這些應成為後續分配模型的資料要求，並由適用 PCR 決定方法。

### 對「除以 3」的判斷

舊滑鼠工作簿 `廢棄回收階段!F8:F10` 都是焚化，分別套用三家焚化廠係數，且各使用相同 `B4` 焚化重量。`F11` 等權平均三個替代估算值。這只能證明原作者如何估算，不能證明三家各占實際流向三分之一，也不能由處理方式種類數推導除數。

官方滑鼠要求文件 §3.5.3 建議以全部焚化的情境評估，並要求隨相關辦法調整及依實際情況選取二級數據；這不構成任選三廠平均的依據，也不能直接核准舊表先扣除回收重量的做法。[來源：官方滑鼠要求文件，印刷 p.8](https://cfp.moenv.gov.tw/Carbon/WebPage/PCR_FileDownload.ashx?fid=43deeca1-9fb6-4906-a71c-a27a9e62a019&sid=f)。

GHG Product Standard §8.2／表8.1要求從技術、地理、時間、完整性及可靠性評估資料；完整性包含統計代表性。[來源：印刷 pp.48、55](https://ghgprotocol.org/sites/default/files/standards/Product-Life-Cycle-Accounting-Reporting-Standard_041613.pdf)。依此對本案例的推論：若三列是替代情境，直接加總會重複計算同一重量；若確有分流，應依各流向實際量或有依據的比例與相應係數計算，再加總。等權平均需要代表性依據，不能僅因有三筆資料就採用。架構應分開「實際流向」與「替代估算情境」，並保存權重及依據，不硬編碼三等分，也不無條件移除除數。
