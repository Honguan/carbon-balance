# PCR 規則版本模型

## 版本邊界

`pcr_versions.rule_set_id` 是同一 PCR 規則族群的穩定識別；`id` 是單一不可變版本識別。新版本以
`supersedes_version_id` 指向前版。草稿可在審查前修正；發布後內容與階段規則不可修改，只能撤回、
標記被取代或建立新版本。既有 Calculation Run 保存原 PCR 版本識別，不因規則更新而改寫。

## 規則結構

每個版本保存：

- 登錄編號、產品分類範圍、版本、必要的核准／生效／到期日。
- 來源參照與物件儲存鍵；原始檔經惡意程式掃描後，由檔案位元組自動計算 SHA-256。
- 功能單位模式、標示單位、系統邊界、允許分配方法與截斷門檻。
- 公式規則版本、四捨五入小數位數與報告要求。
- 五階段的 `Mandatory`、`Optional` 或 `Prohibited` 規則。
- 各階段允許的 `ActivityDataKind` 與活動必填欄位。

分類與功能單位模式可用逗號分隔；尾端 `*` 表示不區分大小寫的前綴比對。受控單位、邊界及分配
方法採不區分大小寫的完整值比對。

## 匯入、審查與發布

1. 管理者建立草稿並上傳原始文件；系統掃描、儲存檔案並計算 SHA-256。
2. 管理者輸入機器可執行條件及五階段規則。
3. 另一位具 MFA 的管理者核准審查；建立者不得自我核准。自訂規則必須另填理由並取得核准。
4. 只有來源檔案掃描為 `Clean`、SHA-256 有效、規則完整且審查核准的草稿可以發布。
5. 發布取代版本時，前版標記為被取代；畫面列出仍綁定各版本的盤查數量。

歷史資料若沒有受控物件儲存鍵或掃描結果，執行期會視為不可選用；歷史 Calculation Run 保持不變。

## 執行時驗證

建立盤查時先驗證 PCR 的發布狀態、日期、產品分類、功能／標示單位、系統邊界、分配方法及階段
必要性。建立 Calculation Run 前再次驗證，並加查必要階段至少一筆活動、活動類型及必填欄位。
標示單位使用版本化單位目錄代碼。Calculation Run 快照另保存並雜湊 PCR 指定的公式版本、截斷門檻、
四捨五入位數及報告要求；公式版本由計算引擎的受控登錄表解析，不接受任意版本。
截斷門檻是盤查完整性與報告規則，不會在計算時靜默刪除活動；排除項目必須在盤查排除說明中留下依據。
四捨五入只用於報告顯示，計算明細與階段／產品總和保留 `decimal` 原始精度。
所有違規均回傳穩定的 `PCR-*` 代碼與可定位的實體識別。
