# Golden reference suite（golden-suite-v1）

`Cases/*-cases.json` 是版本化的參考案例；`GoldenCaseSuiteTests` 讓每個案例經過正式的單位目錄、活動量公式、計算引擎與送審就緒檢查，再與檔案中的預期值比較。CI 以案例 ID 分別回報，失敗訊息列出每個欄位的預期值、實際值與差額。

## 規則

- 預期值由人工逐式手算，推導寫在各案例的 `derivation`；不得以引擎輸出覆寫預期值。若引擎與案例不一致，先查明哪一方錯誤。
- 比較採 decimal 完全相等（容差 0）；`2.50` 與 `2.5` 視為相等。
- 引擎保存完整精度，不捨入；PCR `roundingDecimalPlaces` 只在報表輸出時逐列格式化（GC-009）。
- 每個案例記錄 PCR、規則集、GWP、單位目錄版本（檔案層級 `versions`，可由案例覆寫），以及每個係數的版本號與資料集版本。執行器檢查計算結果保存這些版本，且每筆明細使用案例指定的係數版本。
- 執行器另外檢查每個成功案例的明細加總、階段加總與產品總計一致。
- `Cases/units-p0-v2.json` 與 `CarbonFootprintDbContext` 的 `units-p0-v2` 種子資料相同；種子變更時須同步更新該檔並重審案例。
- `Suite_IsVersionedTraceableAndCoversEveryRequiredCategory` 會檢查案例 ID 不重複、版本與手算推導完整，且每個必要類別至少有一個案例。

## 尚待領域確認（不在本套件中自行決定）

- 報表捨入的中點規則，以及先逐列捨入再加總、或先加總再捨入；目前報表逐列格式化，本套件不斷言捨入後的數值。
- 係數有效性目前只檢查活動迄日；係數是否須涵蓋整個活動期間，需要領域決定。
- 共用資源分配池（#24）、多段運輸模型（#26）、不確定性（#23）尚未實作，所以沒有對應案例；功能完成時再新增案例。
- 本套件只是工程參考，不代表經核准的 Golden Case；正式接受依 [UAT 簽核](../../docs/release/P0_UAT_SIGNOFF.md) 記錄（DEC-007）。
